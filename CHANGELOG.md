### Ajouté

- Interface : réglages libres clé/valeur pour SSH et Git, en listes modifiables (ajouter, modifier, activer, supprimer). SSH : des « options avancées » sous chaque serveur et des options communes à tous (`Host *`) ; Git : une rubrique « Autres réglages » (`section.nom` et sa valeur). Aucune clé n'est refusée pour ce qu'elle fait, un avertissement le dit (seuls `Host`, `Match`, les champs déjà gérés, `alias.*`, `include` sont refusés) ; avant d'appliquer, le vrai `ssh` lit les options et refuse celles qu'il ne comprend pas, sans toucher à ce qui est déjà appliqué. Les configurations enregistrées avant restent lisibles. Le formulaire d'un serveur porte aussi ses options avancées, et « Reprendre » un serveur de `~/.ssh/config` emporte ses autres options (`ProxyCommand`, `Compression`…), sauf celles qu'on perdrait (option écrite deux fois, deuxième `IdentityFile`…). Quand une configuration est enregistrée mais ne peut pas être appliquée (option refusée par `ssh`, fichier impossible à écrire), l'interface le dit en français (nouveau code d'erreur `notApplied`) et garde le message visible en haut de l'écran.
- Interface : la rubrique « Machine » gère aussi les serveurs SSH, dans un onglet « SSH » : nom, machine, utilisateur, port, clé privée (dans `~/.ssh`), rebonds (`ProxyJump`) et transmission de l'agent, avec un interrupteur par serveur. Les serveurs activés sont écrits dans `~/.config/hubergamof/ssh_config`, inclus par un bloc posé tout en haut de `~/.ssh/config` (pour `ssh`, la première valeur l'emporte, et un `Include` après un `Host` ne vaudrait que pour lui) ; ce fichier reste sinon tel quel. Les serveurs trouvés dans `~/.ssh/config` sont montrés à part et peuvent être repris : leur section d'origine est alors commentée (préfixe `#hubergamof-off#`), ce qui permet de les désactiver vraiment ; supprimés de la configuration, ils retrouvent leur section. Seules les options qui ne lancent aucun programme sont gérées : un serveur qui utilise `ProxyCommand`, `LocalCommand`… ne peut pas être repris, et une section commentée qui en contient n'est jamais rétablie. Nouveaux messages `refreshSsh`, `updateSsh` et `ssh`. La gestion des clés viendra ensuite.
- Modules au niveau de l'application (suite) : Teams, Audio, IntelliJ et Claude vivent désormais dans l'application, comme Pomodoro : une seule instance (`app-teams`, `app-audio`… ou celle de `config/modules.json`) que les decks, le menu circulaire et l'interface partagent ; les réglages enregistrés sur un deck deviennent ceux de l'application. Un module partage aussi ses pages (`Module::page_ids`, `ModuleView.pages`) : un deck affiche et pilote les pages d'une instance de l'application. Docker et Notifications restent par deck pour l'instant. Un seul jeu de réglages pour toute l'application : si les réglages d'un deck diffèrent de ceux de `modules.json`, ceux de l'application sont gardés (le journal le signale).
- Menu circulaire : la pétale de Teams affiche en badge sur l'icône le nombre de notifications de Teams (celui de la fenêtre : rail et titre), `99+` au-delà de 99, rien à zéro (`Module::radial_badge`). Le statut « En appel » et la durée de Teams atteignent maintenant le vrai menu (il ne lisait que les modules de l'application).
- Interface : la rubrique « Machine » gère aussi la configuration Git, dans un onglet « Git » : identité (`user.name`, `user.email`), signature des commits (OpenPGP, SSH ou X.509), réglages (première branche, comportement de `git pull`, éditeur, gestion des mots de passe), alias Git, et identités par dossier (nom, adresse et clé propres aux dépôts d'un dossier de `~`, par `includeIf "gitdir:"`). Tout est écrit dans des fichiers de HuBergamof (`~/.config/hubergamof/gitconfig` et un fichier par identité de dossier) inclus par un bloc délimité à la fin de `~/.gitconfig`, qui reste sinon tel quel ; une valeur de HuBergamof l'emporte sur celles qui précèdent. Les valeurs que Git trouve déjà ailleurs (`git config --list`) sont montrées à part, et les alias trouvés peuvent être repris : leur ligne d'origine est alors commentée (préfixe `#hubergamof-off#`), ce qui permet de les désactiver vraiment depuis l'interface ; supprimés de la configuration, ils retrouvent leur ligne. Un alias défini dans un autre fichier que `~/.gitconfig` ou `~/.config/git/config` ne peut pas être repris. Git exécutant certaines valeurs, les alias qui lancent une commande du shell (`!…`) ou une option de Git (`-c …`) sont refusés, `credential.helper` vient d'une liste fermée et `core.editor` d'une liste d'éditeurs ou du chemin d'un éditeur simple (`vim`, `nano`…, jamais un shell), et un dossier d'identité ne peut pas passer par un lien. Nouveaux messages `refreshGit`, `updateGit` et `git`.
- Menu circulaire : actions de pétale. En survolant le pétale d'un module, un arc s'ouvre devant lui avec ses actions du moment (glyphe, libellé de l'action visée, compteur en pastille, glyphe barré quand le micro ou la caméra est coupé) ; relâcher le bouton ou cliquer sur une tranche la lance, le clic sur le corps du pétale garde l'action principale. Un module les décrit par `Module::radial_items` (`RadialItem`, `RadialGlyph`, `RadialItemState`) ; elles changent pendant que le menu est ouvert. Pomodoro : démarrer, pause ou reprendre, étape suivante, remise à zéro. Audio : couper ou rétablir le micro et le son. Teams : conversations et activités (avec le nombre de non lus), et pendant un appel micro, caméra, raccrocher et retour à l'appel (nouvelles actions `conversations`, `activity`, `return-to-call`).
- Docker : les conteneurs sont triés par état puis par nom, dans chaque projet compose comme parmi les conteneurs isolés : en erreur (health check en échec, redémarrage en boucle, mort), en attente (health check en cours, en pause, en arrêt ou suppression), lancé, stoppé (ou créé), puis les services sans conteneur ; les projets restent en premier, par ordre alphabétique. Une touche change de place quand l'état de son conteneur change.
- Teams : pendant un appel, la touche « Raccrocher » montre la durée de l'appel en texte sur le haut de l'icône, qui garde sa taille (`12:34`, puis `1:02:03`), celle que Teams affiche dans sa fenêtre (#97). L'extension la lit (`elapsedSeconds`) ; le gestionnaire la fait avancer seconde par seconde, et la recale à chaque rapport. Sans durée lue, il compte depuis le moment où il a vu l'appel. Une touche peut désormais porter un texte en haut (`KeyContent::caption`). La pétale de Teams dans le menu circulaire dit aussi qu'un appel est en cours, avec la durée (`En appel` / `12:34`, mise à jour pendant que le menu reste ouvert), ou qu'un appel entrant sonne (`Appel entrant`, sans le nom de l'appelant). **Recharger l'extension** (`hubergamof install-extension`) pour profiter de la durée de Teams.
- Interface : une page « Modules » pilote le Pomodoro de l'application : étape, compteur et temps restant en direct (les mêmes que sur la molette du deck et dans le menu circulaire), boutons démarrer ou mettre en pause, passer, remettre à zéro, et réglages enregistrés au fil de la saisie, partagés par tous les onglets et tous les decks.
- Verrouillage : tant que l'ordinateur est verrouillé, le gestionnaire refuse tout ce qui agit ou change quelque chose depuis l'interface (actions, réglages, configuration, mises à jour, téléversements, export et import) et la page passe en lecture seule avec un bandeau.
- Menu circulaire : la pétale de Pomodoro montre l'étape et son rang (`Focus 2/4`) et le temps restant (`12:34`, avec `pause` ou `prêt` quand le minuteur ne tourne pas), mis à jour pendant que le menu reste ouvert. Un module peut dire ce que sa pétale montre sous son nom (`Module::radial_status`).
- Un deck qui place Pomodoro (molette, bande, touche) montre et pilote désormais le minuteur de l'application au lieu d'en avoir un à lui : tous les decks, le menu circulaire et les vibrations partagent le même minuteur, qui tourne aussi sans deck. Les réglages enregistrés sur un deck deviennent ceux de l'application (écrits dans `config/modules.json` ; au premier démarrage, ceux du premier deck qui en a). Aucun changement dans l'interface.
- Modules au niveau de l'application (étape 3a) : un hôte (`ModuleHost`) fait vivre l'instance de Pomodoro indépendamment de tout deck (réglages dans `config/modules.json`, créé vide au premier démarrage). Le menu circulaire de la souris peut lancer, mettre en pause, passer ou remettre à zéro un minuteur même sans aucun Stream Deck, et la fin d'une étape fait vibrer la souris. À l'arrêt propre du gestionnaire, Pomodoro se met en pause avec son temps restant et le retrouve ainsi au démarrage suivant (un plantage reprend par l'échéance). Un deck qui place Pomodoro garde pour l'instant son propre minuteur, que l'étape suivante rattache à celui de l'application.
- Pomodoro : l'étape où l'on en est survit à un redémarrage du gestionnaire (étape, numéro du pomodoro, en marche ou en pause, temps restant), mais pas à un redémarrage de la machine. L'état est gardé dans le répertoire d'exécution de la session (`$XDG_RUNTIME_DIR/hubergamof/`, fichier privé). Un deck débranché puis rebranché retrouve aussi son minuteur. Première étape de la mise des modules au niveau de l'application (`docs/decisions.md`, 2026-11-22).

- Interface : une rubrique « Machine » gère les alias shell de l'ordinateur : formulaire d'ajout, interrupteur activé ou non (un alias activé est écrit dans `~/.config/hubergamof/aliases.sh`, chargé par `~/.bashrc` et `~/.zshrc` ; désactivé ou supprimé, il est retiré du système), et liste à part des alias déjà présents dans les fichiers du shell, avec un bouton pour les intégrer. L'état du système n'est relu que quand la page s'affiche. Un alias de la configuration voit sa ligne d'origine commentée dans les fichiers du shell (préfixe `: #hubergamof-off#`), ce qui permet de le désactiver vraiment ; supprimé de la configuration, il retrouve sa ligne.

### Corrigé

- Docker : sur la page d'un projet, la ligne des actions (tout démarrer, tout arrêter, monter, démonter) reste fixe ; seuls les conteneurs défilent en dessous (#90).
- Revue des spécialistes des souris MX : la force haptique, qui vit dans la mémoire de la souris, n'est plus réécrite à chaque application d'une configuration (un curseur de sensibilité glissé, ou une souris qui revient après un faux silence, l'usaient) : seuls les réglages modifiés sont écrits, et la force est lue puis écrite seulement si elle diffère. Un refus de vibration ou de bascule de molette n'entre plus dans la liste des réglages refusés (elle grossissait à chaque essai tant que la souris ne répondait pas). Une souris éteinte n'est plus sollicitée pour vibrer et sa batterie redevient inconnue, relue dès son retour ; une batterie hors de 1 à 100 % n'est pas crue. Le texte du pétale allumé du menu est sombre (le blanc sur bergamote ne se lisait pas), aperçu et vrai menu ; la page du menu n'a plus de défilement horizontal à 320 px ; la barre d'enregistrement ne masque plus l'élément focalisé ; le mouvement réduit est respecté ; la batterie faible est dite en toutes lettres ; l'aperçu du menu est vérifié contre la géométrie du vrai menu par un fichier de référence.
- Souris Logitech MX : une souris éteinte quitte la liste de l'interface, et y revient quand elle se rallume. Le récepteur n'annonce pas toujours l'extinction (avec l'interrupteur de la MX Master 4 et de la MX Anywhere 3S, rien n'arrive) : le gestionnaire vérifie donc aussi, toutes les 3 secondes, que la souris répond à un ping (lecture seule), et la retire de la liste après deux silences de suite ; au premier retour de réponse, elle est listée de nouveau et sa configuration réappliquée.
- Souris Logitech MX : servir une souris (`--mice`) ne change plus ses réglages sans que la personne l'ait demandé. La première configuration d'une souris reprend ce qu'elle a (sensibilité, mode et seuil de la molette, haute résolution, défilement naturel, molette du pouce, force haptique) au lieu de valeurs fixes, et à l'arrêt (ou si le fil plante) le gestionnaire remet les réglages que la souris avait avant lui. `mouse-test info` affiche aussi les drapeaux de la molette.
- Souris Logitech MX : une souris endormie ne rendait pas ses boutons à l'arrêt (ses premières requêtes restaient sans réponse) ; elle est réveillée (jusqu'à trois pings) avant d'appliquer une configuration et avant de rendre les boutons, y compris à la destruction de la session.
- Molettes : « Affecter » une fonction qui retire un module placé nulle part ailleurs (sauf fonctions du gestionnaire) demande maintenant confirmation, comme le retrait d'une touche ; ses réglages seraient perdus (#69).
- Interface : les textes d'aide sous les touches (défilement par la molette Navigation, déplacement d'une touche) reviennent à la ligne au lieu d'élargir le panneau qui représente le Stream Deck ; test de composant `KeyGrid` (#67).

### Corrigé

### Retiré

- Commande `hubergamof mouse-probe` (inventaire en lecture seule des appareils Logitech) : inutile maintenant que les deux modèles sont pris en charge ; `mouse-test info` lit l'état d'une souris. Ses relevés restent dans `docs/mouse-hidpp.md`.

### Modifié

- Souris Logitech MX : le gestionnaire les sert par défaut (sensibilité, molettes, boutons, menu circulaire), sans option. `--no-mice` coupe tout (pour garder Solaar ou logiops, qui détournent les mêmes boutons) ; `--mice` reste accepté. Une première configuration détourne le bouton du menu circulaire de la souris, comme le décide `MouseConfig::default_for`.

### Ajouté

- Interface des souris : l'aperçu du menu circulaire est dessiné comme le vrai menu (anneau découpé en pétales à côtés parallèles, icône et nom, pétale choisi en bergamote), et la section « Menu circulaire » est toujours proposée, même avec un seul type d'appareil connecté (ou aucun).
- Interface des souris, alignement sur la maquette, étape 6 : l'en-tête d'une souris montre sa batterie (« Batterie 76 % », « · en charge », en alerte à 20 % ou moins hors charge). Le gestionnaire la lit sans rien écrire, au branchement puis toutes les 5 minutes ; le message `mouseStatus` porte maintenant aussi `battery` (absent tant qu'elle est inconnue). Les souris simulées de `--demo` en ont une.
- Interface des souris, alignement sur la maquette, étape 5 : le menu circulaire a sa propre section (à côté de « Stream Deck » et « Souris »), avec un aperçu des pétales affichés (un pétale choisi dit ce que fait un clic dessus), le bouton qui ouvre le menu sur la souris choisie et l'éditeur des entrées.
- Interface des souris, alignement sur la maquette, étape 4 : l'onglet Haptique a un moniteur qui dessine et joue la forme d'onde (la souris dessinée tremble selon la force), l'intensité en boutons segmentés, les événements regroupés par module avec « Tout le module » (état intermédiaire quand une partie seulement est active) et, pour chaque événement, l'interrupteur, la forme d'onde (la changer la joue aussitôt), son petit graphique et un bouton « Jouer ». Nouveau message `playHaptic` (interface → gestionnaire) : joue une forme d'onde sur la souris choisie, à sa force réglée, rien si elle est coupée, au plus une fois tous les 600 ms par souris.
- Interface des souris, alignement sur la maquette, étape 3 : l'onglet Touches montre la souris de dessus et de côté (MX Master 4 et MX Anywhere 3S) avec un repère numéroté par contrôle, cliquable ou au clavier (Entrée, Espace), la liste des contrôles avec ce que chacun fait, et l'éditeur du contrôle choisi (action, module et action, raccourci, « Rétablir l'action d'origine » ; les deux clics et la molette du pouce sont seulement décrits). `--demo` liste maintenant aussi une MX Anywhere 3S simulée. Les schémas sont des données dessinées élément par élément, jamais injectées comme balisage.
- Interface des souris, alignement sur la maquette, étape 2 : la page d'une souris a un en-tête (nom, « Connectée · Logi Bolt », « Retour haptique » pour les modèles haptiques) et trois onglets (Touches, Pointeur et molette, Haptique, ce dernier seulement pour les modèles haptiques ; flèches, Début et Fin au clavier) ; plusieurs souris se choisissent par boutons segmentés ; les réglages du pointeur et des molettes sont en lignes « nom, explication, contrôle » avec des curseurs (sensibilité, seuil du mode automatique, vitesse de la molette du pouce) et des interrupteurs.

Les raccourcis disent aussi ce que les touches donnent sur le clavier de la personne quand ce n'est pas le clavier américain (Ctrl + A devient « Ctrl + Q » sur AZERTY) ; le clavier est lu par `navigator.keyboard` quand le navigateur le donne, et appris sinon des touches tapées sur la page (Brave le cache), gardé dans le navigateur ; en attendant, la disposition habituelle de la langue du navigateur (AZERTY pour le français, QWERTZ pour l'allemand) sert d'indice, présenté comme tel. La page dit aussi que le navigateur garde certaines combinaisons (Ctrl + Q, Ctrl + W…), qui ne s'enregistrent pas en appuyant sur les touches mais s'écrivent dans le champ.

- Souris Logitech MX : une souris éteinte puis rallumée (notification de lien `0x41` du récepteur, relevée sur une MX Master 4) est reconfigurée : à l'extinction les boutons tenus sont relâchés, au retour la configuration complète est réappliquée (les boutons détournés ne survivent pas à l'extinction).

- Interface des souris, étapes 3 à 7 : page « Souris » (bascule Stream Deck / Souris quand les deux sont là) avec les boutons de la souris (comportement d'origine, désactivé, clic, double clic, bascule de molette, menu circulaire, action d'un module, raccourci clavier saisi ou enregistré en appuyant sur les touches), le pointeur (sensibilité) et les molettes (mode, seuil, défilement naturel, haute résolution, molette du pouce), les vibrations des modèles haptiques (force, événements des modules : activé, forme d'onde) et le menu circulaire (entrées affichées, ordre, action du clic, durée du maintien, animation, vibrations) ; chaque changement est enregistré à l'instant et la page dit s'il l'est ou s'il a été refusé. `--demo` liste une MX Master 4 simulée pour les tests de bout en bout.
- Interface des souris, étape 2 (état) : `MouseState` suit les souris connectées, la configuration de la souris choisie et le menu circulaire ; la file d'enregistrements sérialisés du Stream Deck (`EditQueue`) est factorisée pour les trois ; fonctions d'édition (`mouse-edits.ts`) et conversion d'une saisie clavier en raccourci (`shortcut.ts`), avec tests.
- Interface des souris, étape 1 (contrat) : le catalogue des modules transporte les actions que chaque module offre au menu circulaire (`radialActions`, la première est celle d'un clic sur son pétale) et les événements haptiques qu'il peut signaler (`hapticEvents`), pour que l'interface de configuration les propose ; `RadialActionDescriptor` et `HapticEventDescriptor` sont exportés vers TypeScript.
- Souris Logitech MX, étape 6c (haptique du menu) : le menu circulaire se sent : une vibration légère à l'ouverture, une plus fine quand le pointeur aborde un pétale, une nette au choix ; l'option « haptique » du menu les coupe, et le niveau « coupé » de la souris aussi. La souris reçoit désormais ses ordres toutes les 40 ms (200 ms avant), pour que la vibration suive le pointeur.
- Souris Logitech MX, étape 6b (haptique des modules) : les modules signalent des événements sur la souris à retour haptique (MX Master 4) : fin d'étape du Pomodoro, appel entrant, réunion qui approche et nouveau message de Teams, micro ou son coupé depuis le menu circulaire ; chaque événement a une onde par défaut, que le réglage de la souris peut changer ou couper. - Souris Logitech MX, étape 6a (actions des modules) : choisir une entrée du menu circulaire lance l'action du module sur ton Stream Deck : Pomodoro (démarrer ou pause, passer, remise à zéro), Audio (couper le micro, couper le son), Teams (micro, caméra, raccrocher), IntelliJ (ouvrir). Les modules déclarent ces actions dans l'API (`radial_actions`, `on_radial_action`).
- Menu circulaire sous GNOME : le menu se place d'après un vrai mouvement du pointeur (impulsion d'un pixel par le périphérique virtuel pendant qu'il attend sa position) au lieu de la position d'entrée de XWayland, qui pouvait être périmée.
- Souris Logitech MX, étape 5e (GNOME/X11) : sur un bureau sans layer-shell (Ubuntu/GNOME), le menu circulaire s'affiche dans une fenêtre X11 plein écran transparente (Xorg, ou XWayland sous une session Wayland) ; le gestionnaire essaie d'abord layer-shell (KDE) puis X11. `hubergamof radial-preview` l'essaie aussi.

Sous la bande, un rappel par molette dit ce qu'elle fait (rotation, clic) et suit l'état (« Muet » puis « Réactiver »). - Interface : aperçu de la bande (valeurs d'exemple, suit le thème et les options) ; un clic ouvre ses réglages (thème, secondes, barre de progression du pomodoro, courbes, période des mesures, seuil d'alerte).

- Lanceur de bureau « HuBergamof » avec son icône (paquets et `make install`) : il relance le service utilisateur quand le gestionnaire a été fermé (quitté, arrêté, abandonné par systemd après des échecs), puis ouvre l'interface. - Release : workflow manuel `release.yml` (depuis `main` seulement, CI verte exigée sur le commit, attente d'un run en cours). Version déduite des Conventional Commits depuis le dernier tag (1.0.0 au début, forçage d'un patch possible), release GitHub avec note, `SHA256SUMS` et tag `vX.Y.Z`.

Cibles `make package*`, job CI `package` (lintian, installation en conteneurs Ubuntu et Arch).
- API des modules : `Command::BackTo(PageId)` revient à une page du module en fermant celles qui sont ouvertes au-dessus.
- Contrat : code d'erreur `busy` (409) quand une boîte de dialogue de fichier est déjà ouverte ; le sélecteur de fichier est décrit par le réglage (`FileChooser`, `EntryNaming`, bornes `max_entries`/`max_name_chars`, textes) et la route devient `POST /api/file-chooser` (`FileChooserRequest { module, setting }`) : l'interface de liste de fichiers ne contient plus rien de propre à compose.

- Module Docker : chaque fichier compose déclaré a un nom et une icône au choix. Les réglages listent les fichiers ajoutés (icône, nom, chemin) ; on les ajoute avec le sélecteur de fichier natif du bureau (portail `xdg-desktop-portal`, qui donne le vrai chemin, ce qu'un `<input type="file">` ne fait pas), puis on les modifie ou les supprime sur place. Sans portail (ou sans bureau), le chemin se saisit. Le nom remplace celui du projet compose sur la touche et dans les titres ; l'icône remplace les couches. Les icônes sont stockées comme les images de touche (même contrôle, export/import zip, nettoyage des inutilisées) et lues par les modules via `ModuleContext::images()`.

### Corrigé

- Bande tactile : les points de navigation n'apparaissent que si des lignes sont cachées, un par position de défilement (le dernier point est donc atteignable) ; le rappel « Retour » de la molette Navigation disparaît sur l'accueil ; le menu du pomodoro se rafraîchit plus vite (seules les colonnes modifiées de la bande sont écrites, ombre du menu moins coûteuse) et son rappel devient « Menu pomodoro » (un rappel seul dispose de toute la largeur de sa molette).
- Interface : les touches sont centrées au-dessus des molettes.
- Module Docker : le ✓/⚠ d'un `up`/`down` sur un service s'affiche sur son entrée (conteneur ou service sans conteneur) et non sur la touche du projet.

- `make dev` : le sélecteur de fichier compose ouvre maintenant la vraie boîte du bureau. `--demo` le remplaçait par une réponse fixe ; cette réponse est devenue l'option `--file-chooser-answer <fichier>`, que seuls les tests e2e passent.

- Sélecteur de fichier compose : le signal de réponse du portail est écouté sans dépendre du nom du service (activé à la demande sous Ubuntu), la réponse est reconnue par le chemin de la requête renvoyé par le portail, et une erreur D-Bus réelle n'est plus déguisée en « indisponible » (elle est journalisée).
- Réglages Docker : un fichier compose sans image personnalisée montre l'icône des projets compose (les couches) et non la baleine du module (`ModuleFactory::setting_item_icon`, `CatalogModule::setting_icons`).

- Image Docker : `zlib1g` est mis à jour dans l'étage d'exécution (deux CVE HIGH corrigées par Debian, absentes du digest épinglé de `debian:trixie-slim`), ce qui faisait échouer le scan Trivy de la CI.

- Bande tactile incomplète au premier démarrage ou après un rebranchement : seules les zones qui changeaient (l'horloge) s'affichaient, les écritures faites juste à la connexion étant perdues par l'appareil. Toute la bande est désormais réécrite une fois, 400 ms après le premier dessin.

- Applications lancées par le gestionnaire (IntelliJ, Claude) : elles prennent aussi leur propre groupe de processus, pour ne plus se fermer avec le gestionnaire lorsqu'un signal (Ctrl-C dans le terminal) vise le groupe de celui-ci.

- Module Audio sur Ubuntu : `pactl` n'y est pas installé par défaut (paquet `pulseaudio-utils`), contrairement à ce que disait le README. La bande affiche désormais « pactl absent » ou « pactl trop ancien » (version < 16) au lieu de « Audio indisponible », le journal indique le paquet à installer, `make install` avertit si `pactl` manque ou est trop ancien, et le README et le CLAUDE.md corrigent le prérequis (`wpctl`, inutilisé, retiré).

- Build sur une machine neuve avec un Node 24 antérieur à 24.12 : le Corepack livré ne sait pas lancer pnpm 12 (`Cannot find module …/pnpm.cjs`). `engines.node` passe à `>=24.12.0`, `make` vérifie la version de Node avant d'installer l'UI (`make check-node`) avec un message de remède, et le README décrit le dépannage (cache Corepack à effacer, réseau).

- Tests d'intégration instables à chaque changement de minute : l'heure murale du module Horloge est désormais injectée (`BuiltinServices::wall_clock`), figée dans `BuiltinServices::simulated()` ; `--demo` garde l'heure réelle.
