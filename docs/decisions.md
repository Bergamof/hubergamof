# Journal des décisions techniques

Journal chronologique (décisions d'Adrien et choix de conception). Le résumé des décisions structurantes est dans `CLAUDE.md` ; ajouter ici toute nouvelle décision datée. Risques acceptés et décisions de sécurité : `docs/security.md`.

- 2026-10-28 — Rust pour le gestionnaire : binaire natif léger ; réticence à JS/TS hors web.
- 2026-10-28 — Un seul binaire servant UI statique + WebSocket sur `127.0.0.1:7878` : un processus, temps réel simple.
- 2026-10-28 — Contrôle strict `Origin`/`Host`, sans jeton de session : un site malveillant ne doit pas pouvoir piloter le gestionnaire (CSRF WebSocket, DNS rebinding).
- 2026-11-02 — Appuis simulés (`PressKey`/`RotateDial`/`PressDial`) refusés hors `--demo` (`SimulatedInput`, `ErrorCode::InputRefused`) : sur le vrai matériel, les actions ne viennent que de l'appareil, l'UI ne fait que configurer et afficher. Ferme l'élévation vers root via Docker par un processus local (Origin/Host forgeables hors navigateur) ; jeton de session écarté tant que l'UI n'a pas d'action directe.
- 2026-11-03 — UI sans affichage miroir dans un premier temps (Adrien) : chaque touche/molette montre l'icône de son module ; `liveState` gardé, sur demande.
- 2026-10-28 — Pas d'API REST publique (routes HTTP internes upload/export/import) : règles REST non appliquées.
- 2026-11-03 — Export en zip (`config.json` lisible + `images/`) plutôt qu'en JSON à images base64 (Adrien) ; import vers un autre modèle autorisé (molettes adaptées) ; images personnalisées sur les touches seulement.
- 2026-10-28 — `DeckBackend` virtuel (`--demo`) : tests, dev UI, Playwright et Lighthouse sans matériel.
- 2026-10-28 — Dockerfile = build reproductible + mode `--demo` (CI/Lighthouse) ; exécution réelle via systemd (USB, D-Bus, audio de session).
- 2026-10-28 — Config dans le projet (`config/devices/`, ignoré par git ; `config/example/` versionné) ; déplacement vers `~/.config` prévu plus tard.
- 2026-10-28 — Un thread par appareil matériel (sans la feature `async` d'`elgato-streamdeck`) : `HidDevice` n'est pas `Sync`, la feature utilise `block_in_place`.
- 2026-10-28 — Texte rendu via `usvg`/`resvg` (pas `ab_glyph`, qui tire `ttf-parser`, RUSTSEC-2026-0192).
- 2026-11-05 — Icônes par défaut des modules : logos officiels (Docker, IntelliJ, Claude) en pictogrammes colorés sur fond noir, usage personnel non distribué (Adrien) ; remplace « jamais de marque ». À revoir si le dépôt devient public. SVG dans `crates/modules/assets/icons/` (`icons::asset!`).
- 2026-11-05 — Plus aucun cadre sur les touches (Adrien) : `KeyState::Active` ne dessine rien (l'état se voit par l'icône : badges Docker, tick vert audio), `Attention` garde seulement son fond orange. Libellé de touche : une seule ligne, police 0,13 × hauteur, sous l'icône (zone d'image réduite), jamais par-dessus.
- 2026-11-12 — Bande tactile globale (Adrien) : elle n'est plus liée aux molettes ; l'hôte la dessine (heure, date, charge CPU/RAM/swap, page, volume, pomodoro) avec un rappel par molette dessous ; maquette retenue « Papier » (clair par défaut, sombre au choix), menu du pomodoro en fenêtre flottante fermée seule après 5 s, pomodoro à l'arrêt visible en discret. Les molettes reçoivent des fonctions (modules : volume, pomodoro ; hôte : navigation, contextuelle (à définir), rien) ; modules horloge et navigation supprimés. Remplace le cadran « Éphéméride ».
- 2026-11-12 — Thème Clair/Sombre par appareil (Adrien) : `DeviceConfig::theme` (schéma 3, migré depuis `strip.theme`) ; les touches ont le fond de la bande dans les deux thèmes, libellé à l'encre du thème (Attention garde son orange et son blanc). Icônes embarquées transparentes (masques SVG pour les découpes) ; images personnalisées transparentes partout (rendu des touches, UI, icônes de notification).
- 2026-11-12 — Placement des modules (Adrien) : un module n'est assignable à une touche que s'il le déclare (`key`) et n'a plusieurs instances que s'il le déclare (`multiple_instances`), refusé par défaut. Sans cela, une seule instance par appareil, aux réglages partagés par sa touche et ses molettes. Un module n'occupe qu'une molette (ferme, même multi-instances). Pomodoro sans touche ; seul Docker en multiple ; Notifications a besoin d'une touche pour lire les non lues. Règles uniques dans `placement.rs` (`violations` + `normalize`) ; config existante/importée normalisée silencieusement + notification de l'hôte sur la bande.
- 2026-11-12 — Molette contextuelle (Adrien) : elle suit la page affichée ; le module de la page déclare, avec la page, les textes de rotation/appui/appui long, qui conditionnent l'appel (rien de déclaré : rien d'affiché, aucune action). Première utilisation : sélection de services d'un compose Docker (une sélection perdue refuse l'action au lieu de l'étendre au projet ; cadre de curseur + pastille ✓ dessinés par l'hôte : seule exception à « aucun cadre » de 2026-11-05 ; appui long non affiché sous la bande ; sélection vidée au lancement ; Up, Down, Démarrer et Arrêter agissent sur les services cochés).
- 2026-11-12 — Notifications actionnables (Adrien) : une notification peut donner un appui à la molette contextuelle (texte affiché au bas de la bande, module appelé puis notification lue). Pomodoro : « Démarrer la pause/le travail » seulement sans `autoStart`, sans effet si l'étape est déjà lancée.
- 2026-11-14 — Verrouillage de l'ordinateur (#43, Adrien) : verrouillé, le deck n'agit plus, sauf les modules qui déclarent `usable_when_locked` (fonctions internes au deck : Notifications, Pomodoro ; jamais une commande sur l'ordinateur), le reste porte un cadenas ; il s'éteint après un délai réglable de l'appareil (5 s par défaut, 0 = reste allumé) ; une entrée le rallume sans action, le déverrouillage aussitôt. Limites : `docs/security.md`.
- 2026-11-16 — Verrouillage par action (Adrien, prépare le module Teams) : une page de module déclare des touches utilisables verrouillé (`KeyContent::usable_when_locked` → `FrameKey`, jamais dans `KeyTarget` ; molette contextuelle et action de notification : `ContextDial::usable_when_locked`) — ignoré sauf capacité `ModuleCapabilities::lock_safe_pages`, appliquée dans `displayed_page` ; une page peut aussi garder le deck allumé (`PageContent::keeps_device_lit` → `Frame::keeps_lit`, `LockState::page_keeps_lit`) ; point de passage `DeviceEngine::dispatch`. Entorse assumée à « jamais une commande sur l'ordinateur » (micro, raccrocher) : `docs/security.md`.
- 2026-11-17 — Module Teams (Adrien) : pas de connexion tierce ni d'ICS ; extension de navigateur (Brave, compte pro) + hôte natif `hubergamof native-host` → socket Unix privé du gestionnaire ; l'extension ne lit que compteur, noms des non lus, état de l'appel et calendrier (ouvert par l'utilisateur) ; micro et raccrocher utilisables verrouillé. Livré en trois volets : pont + module (2a), extension + installation (2b), rappels de réunions + appel entrant actionnable (2c). Spike : `docs/integrations-desktop.md`.
- 2026-11-18 — Teams au premier plan (Adrien) : la touche d'accueil sans non lu ni appel, l'appui sur une conversation non lue et « Revenir à l'appel » mettent la fenêtre de Teams (PWA Brave, `ClassMatch::Contains(<id de la PWA>)`) au premier plan par la couche bureau (`FollowedApp`, lancement `gtk-launch brave-<id>-Default` si fermée) ; ouvrir une conversation = `ManagerRequest::OpenConversation` (identifiant rapporté par l'extension, jamais de navigation : recharger coupe l'appel). Pas de ✓ pour les actions d'appel (l'icône suffit).
- 2026-11-18 — Teams, page d'appel (Adrien) : icônes pour les actions (sans état d'attention) ; avatar de chaque conversation non lue (icône générique sinon) ; non lus sur la seconde ligne pendant un appel, actions épinglées ; noms et avatars masqués verrouillé (option A) ; touche d'accueil utilisable verrouillé pendant un appel. Seules les conversations comptent (pas les canaux de l'onglet Équipes).
- 2026-10-28 — Extensibilité : trait `Module` dès maintenant ; chargement externe (WASM ou sous-processus) plus tard, jamais de `.so`.

- 2026-11-09 — Refonte visuelle de l'UI et identité (Adrien) : accent bergamote, logo en grille de touches formant un « H », polices embarquées (la CSP interdit tout serveur tiers), bannière simple (nom seul, fond transparent, « B » en dégradé doux, sans illustration) uniquement en en-tête de l'UI et du README, icône de tray en pixmap.
