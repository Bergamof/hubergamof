# Architecture détaillée

Référence détaillée, lue à la demande : `CLAUDE.md` n'en garde qu'un résumé. À tenir à jour avec le code (voir aussi `docs/modules.md` pour le détail des modules et `docs/integrations-desktop.md` pour le bureau).

## Crates et flux
- `crates/protocol/` (`hubergamof-protocol`) — messages WebSocket (`ClientMessage`/`ServerMessage`, taggés `type`, camelCase), configuration + `DeviceConfig::validate`, catalogue (`CatalogModule` = `ModuleDescriptor` aplati + icône PNG + réglages par défaut ; `SettingField` → formulaires UI génériques), état en direct (`LiveState`, images en data URL, envoyé seulement si `selectDevice.liveState`). Souris : `mouse/` (`model.rs` : `MouseModel` et ses contrôles ; `action.rs`, `haptic.rs`, `config.rs` : `MouseConfig::validate` contre les capacités du modèle) et `radial.rs` (`RadialMenuConfig`, menu global) ; ces types n'ont pas encore de messages WebSocket (étape 3). Source unique du contrat, exporté en TS par `ts-rs` vers `ui/src/lib/generated/` (+ `index.ts` généré par le test `export_bindings_index`).
- `crates/headset/` (`hubergamof-headset`) — casques Sony (WH-1000XM4) : `frame.rs` (trame MDR, échappement, somme, décodeur de flux), `channel.rs` (`Channel`), `link.rs` (`Link` : acquittements, séquence, renvois, trace), `payload.rs` (demandes `Query` et réglages `AmbientSetting` en valeurs fermées ; lecture `decode` → `Event`), `bluez.rs` (objet `Profile1` + `ConnectProfile` : BlueZ remet le socket RFCOMM, `unsafe` interdit ; `RfcommChannel`), `diagnostics.rs` (actions de `hubergamof headset-test`), `testing.rs` (`FakeHeadset`, feature `test-support`). - Hub commun des rubriques de la machine : `machine/hub.rs`, `Hub<F: Feature>` (alias shell, Git, SSH ensuite). Une rubrique dit seulement `Feature::load`/`save` (le `ConfigStore`), `apply` (sur le `Target` : les fichiers sous un home), `snapshot` (ce qu'on dit aux clients : la configuration et ce que l'ordinateur contient en plus) ; le hub fait le reste : `refresh` (relit, et si le fichier enregistré était invalide, remplacé par une configuration vide, applique cette dernière pour retirer ce que l'ancienne avait posé), `update` (valide, vérifie la révision, sauvegarde, applique, diffuse à tous les clients par `broadcast` même si l'application échoue : la révision a avancé), une seule requête à la fois par sémaphore (la diffusion suit l'ordre des révisions), `HubError<E>` (`Store`, `Apply(E)`, `NoHome`, `Task`), `with_demo_home` (home temporaire). La session WebSocket route les messages d'une rubrique par `refresh_feature`/`update_feature` (génériques) et `machine_message`/`git_message`. Une nouvelle rubrique = une `Feature`, un alias de hub, deux messages du contrat et deux fonctions de message.

UI : onglets « Alias du shell / Git » de `MachinePage` ; `GitPanel` (+ `GitIdentityForm`, `GitSigningForm`, `GitSettingsForm`, `GitFolderForm`, `GitFolderList`, `GitSystemEntries`, `TextField`, `SelectField`, `FormFooter`) ; état `GitState` dans `DeckState.git` ; `git-validation.ts` miroir de `git.rs` (cas partagés dans `crates/protocol/tests/fixtures/git-validation.json`) ; les alias Git réutilisent `AliasForm`/`AliasList`/`SystemAliasList` par la prop `rules` (`alias-rules.ts`). `ServerContext.git` est à fournir dans les tests de serveur.

## Pièges et conventions détaillés
- Bande tactile : les tests du moteur règlent l'heure (`SettableClock`) et comptent les mesures (`CountingProbe`) ; `Fixture::with` prend les molettes en `Option<&str>` (`NAVIGATION_DIAL` = navigation, sinon la fonction `turn` du module fragile). Le rappel d'une molette montre ✓/⚠ à la place de son texte pendant 1 s. Police de la bande : Noto Sans SemiBold seule (pas de gras 700 ni de Light).
- Wayland : mise au premier plan via script KWin sous KDE ; sous GNOME la fenêtre peut seulement clignoter (accepté). Relancer une appli déjà ouverte ne l'active pas.
- Risques acceptés et décisions de sécurité (autres comptes Unix, unité systemd, bornes) : `docs/security.md`.
- Intégrations Claude Desktop / IntelliJ / KWin / zbus 6 (mécanismes, pièges) : `docs/integrations-desktop.md` — à lire avant de toucher ces modules ; détail des modules : `docs/modules.md` (à tenir à jour avec eux).
- Tray sous GNOME : nécessite l'extension AppIndicator (présente par défaut sur Ubuntu).
- Polices : `@font-face` de `routes/layout.css` pointe par chemin relatif vers `node_modules/@fontsource-variable/*/files/*-latin-wght-normal.woff2` (le sous-ensemble latin couvre le français ; `@import` du paquet embarquerait tous les alphabets).
- `ui/src/lib/generated/` est généré : ne jamais l'éditer à la main, lancer `make gen-types` (supprime le dossier puis régénère). `cargo test --workspace` le régénère aussi. Exclu de Prettier/ESLint (non formaté par ts-rs).
- SvelteKit 3 n'a plus l'alias `$lib` : imports via sous-chemins Node `#lib/*` (ex. `import type … from '#lib/generated/index.js'`).
- `pnpm test:e2e` : le `webServer` de Playwright construit l'UI puis la sert (il démarre avant `globalSetup`, d'où le build ici et pas dans le setup), `globalSetup` compile le gestionnaire, chaque test « demo » en lance un (port libre, config temporaire) ; le projet « sans-gestionnaire » sert le build sur `127.0.0.1:4173` avec proxy vers 7878 : rien ne doit tourner sur 7878. Lighthouse audite `hubergamof --demo` sur 7881.
- `.cargo/config.toml` fixe `TS_RS_EXPORT_DIR` et `TS_RS_LARGE_INT=number` (u64/i64 → `number` en TS, pas `bigint`).
- `DeviceModel` reprend un pour un `elgato_streamdeck::info::Kind` (+ `virtual`) ; champs optionnels sérialisés à `null` (`T | null` en TS).
- Requêtes vers des API publiques (crates.io, npm, GitHub) : User-Agent générique, jamais d'information personnelle.
- Images référencées par les réglages (icônes des fichiers compose) : `ModuleDescriptors::descriptor` (implémenté par le registre ; `ConfigStore::new(root, registre)`) les fait compter dans le nettoyage, l'export et l'import (`ConfigStore::prepare_import`) ; un `<input type="file">` ne donne jamais le chemin d'un fichier, d'où le sélecteur natif.
- Environnement de session cloud : `libudev-dev` à installer (`apt-get`), Node 24 requis par pnpm 12 (pas de Node 24 par défaut), Playwright 1.65 attend `chromium-1254` et `chromium_headless_shell-1254` (liens symboliques vers la version préinstallée de `/opt/pw-browsers`).
- Tests navigateur : `toHaveTextContent(/…/)` ne trouve pas un motif au milieu du texte (comparaison entière) ; préférer `getByText(/…/)`. Les `<img>` décoratives (`alt=""`) se lisent par `document.querySelectorAll`.
- Ne pas activer de feature de backend `hidapi` : `elgato-streamdeck` impose `linux-static-hidraw` et deux backends font paniquer le build.
- Un seul gestionnaire peut tenir l'appareil : StreamController (installé chez Adrien, autostart désactivé) entre en conflit ; son plantage a déjà détaché le pilote HID (débrancher/rebrancher).
- Les gestionnaires de module sont attendus un par un dans la boucle de l'appareil : toute E/S longue (Docker, IntelliJ, Claude, audio) passe par une tâche de fond (`TaskSpawner`) + `EventSender` (changement d'état, `on_event`) ou `RedrawHandle` ; une boucle de fond s'arrête quand `send` renvoie `false`.
- `ts-rs` recopie la rustdoc des types du contrat dans le TS : toute retouche de ces commentaires impose `make gen-types`.
- Docker : les services d'un compose (`docker compose config --services`) se lisent en tâche de fond (déclarés : seuls ; autres : à l'ouverture du projet) ; `up`/`down` = `ComposeScope` (`Project` ou `Services(Vec)` : un service, ou les services cochés avec la molette contextuelle ; paramètre de `DockerBackend::compose`, hors de `ComposeTarget`) ; lancer un up/down revient à la page du projet (`Command::BackTo`) et l'opération marque les entrées (`Operation`) ; une action de la page d'un conteneur revient à la page qui le liste (`Command::BackTo`, `container_parent`, choisie au lancement), une à la fois par conteneur (`container_actions`), progression et ✓/⚠ sur son entrée ; le ✓/⚠ final est sur l'entrée du service (conteneur ou service sans conteneur, les deux nommés : la liste n'est pas encore à jour). Module `docker/` découpé : `settings.rs`, `pages.rs`, `actions.rs`, `operation.rs`, `render.rs`, `selection.rs` (curseur et cases de la page d'un projet, par service), `mod.rs` (fabrique, `Docker`, événements).
- `Painter` : la base d'une touche est réutilisée tant que `Face::same_base` dit « identique » ; elle déstructure `KeyFace` sans `..`, donc tout champ ajouté doit y être décidé pour compiler.
- Structs publiques de `module-api` (`PageContent`, `KeyContent`, `ContextDial`) : `#[non_exhaustive]`, construites par constructeurs (`PageContent::new`, `with_context_dial`, `KeyContent::with_icon(..).focused(..).checked(..)`) ; pas de littéral hors de la crate.
- Tests du moteur avec des gestes tenus : laisser le moteur prendre l'appui (`sleep` court en temps simulé) avant d'envoyer l'événement suivant d'une autre source (requête, événement de module) : l'ordre entre sources est aléatoire dans le `select!`.
- Les molettes agissent à l'appui (`DialDown`) ; les touches **au relâchement** (`KeyUp`, tenue < 400 ms ; maintien = libellé sur la bande, sans action) ; un tap de bande lit la notification affichée, sinon, sur le panneau des mesures (`render::is_system_panel`, appui court), bascule `strip.show_history` via `apply_config`. Sous une notification, seul le clic d'une molette de fonction Navigation agit (l’enlève, non lue). Appuis simulés (UI/`--demo`) : immédiats.
- Toute requête vers le gestionnaire doit porter un `Host`/`Origin` autorisé (curl : `-H 'Host: 127.0.0.1:<port>'`). `make dev` doit passer `--dev-origin http://localhost:5173 --dev-origin http://127.0.0.1:5173`.
- UI embarquée : en debug `rust-embed` lit `ui/build/` à l'exécution ; en release elle est embarquée et `build.rs` recompile quand elle change (`make ui-build` avant `cargo build --release`).
- `Renderer` et `ConfigStore` sont synchrones/CPU : les appeler via `spawn_blocking`. Le « défile-t-il ? » d'une notification est mesuré par le rendu (`NotificationImage::scrolls`, rapporté par `Painter::take_scrolls`), jamais par un appel direct depuis la tâche de l'appareil.
- Transparence : `KeyRequest::themed(theme)` pose la touche sur le fond de la bande (`strip::surface`) ; `render_image` (UI, catalogue) et les icônes de notification sont rendus sur `TRANSPARENT` ; `contain` redimensionne en alpha prémultiplié. `Frame::theme` : le `Painter` redessine toutes les touches au changement de thème. Côté UI, `data-device-theme` sur `DeckEditor` pilote les jetons `--screen*` (`ModuleTile`).
- Les appareils n'acceptent que JPEG (BMP pour Original v1/Mini) : toute image passe par le pipeline de rendu.
- Images du `ConfigStore` adressées par contenu : ne jamais réécrire un fichier en place (le mémo des condensats s'appuie sur `(chemin, mtime, taille)`).
- Sources `ImageSource::Bytes` : réservées aux octets à longue durée de vie (icônes) — le mémo des condensats garde un `Weak` qui retient l'allocation ; contenu ponctuel (upload, import) → `Renderer::check_image`. Exception assumée : les avatars des conversations Teams (≤ 16 Kio, gardés tant que la conversation est listée, comparés par contenu donc partagés d'un rapport à l'autre).
- Détection SVG stricte (`ImageKind::sniff`) : document dont l'élément racine est `<svg` ; un texte qui contient `<svg` n'en est pas un (fichier compose déguisé).
- Proxies zbus vers KDE : membres en lowerCamelCase → `#[zbus(name = "…")]` (zbus dérive en PascalCase) ; builders zbus 6 sans `Result` (erreur au `build()`).
- Applications lancées par le gestionnaire : toujours via `desktop::Launch` (scope systemd), sinon elles meurent avec le service ; contraintes sur les valeurs lancées dans `docs/integrations-desktop.md`.
- Attentes des streams du bureau (`WindowChanges`/`NotificationStream::next`) : sûres à l'annulation (lues dans un `select!`) ; tout travail lent va dans une tâche dédiée.
- Notification animée (≈ 15 images/s) : tout ce qui coûte (SVG des rappels des molettes → couche mise en cache dans `Renderer::notification_reminders`, texte → `notification_text`) est dessiné une fois et seulement composité à chaque pas ; la bande couverte puis découverte est réécrite depuis l'image gardée (`PaintedStrip`) sans re-rendu si son contenu n'a pas changé. Ne jamais rasteriser de SVG à chaque pas.
- Version de l'extension Teams = celle du workspace : `set-version.sh` fixe `ui/teams-extension/manifest.json` à la release (copie de travail), l'extension l'annonce par `BrowserReport::Hello` et le pont journalise un `warn` si elle diffère de `CARGO_PKG_VERSION` ; en local les deux valent `0.1.0` (les monter ensemble, `set-version.sh` est strict : il échoue sans ligne `"version"` indentée d'une tabulation).
- Les tests de panique des modules écrivent le message du panic hook sur stderr (`fragile …`) : attendu.
